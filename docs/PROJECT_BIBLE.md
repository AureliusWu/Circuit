# 《回路 / Circuit》项目圣经 v0.1

## 1. 一句话定位

一款以城市配电抢修为入口的中式民俗恐怖叙事 AVG：玩家处理的每个“灵异事件”，最初都必须能被解释为一个真实的电气故障。

## 2. 主角

主角长期固定为同一人：**梧城供电公司基层配电运检员，兼参与故障抢修**。

不采用多主角群像作为主结构。每章由新的报修人、住户、死者家属、同事或地方人物承担“章节关键人物”。必要时允许极短的他人视角，用于制造信息差，但不得削弱玩家对主角的长期代入。

主角的专业能力必须真实参与叙事：

- 接收工单与故障范围判断
- 停送电与验电逻辑
- 电表、台账、用户信息核对
- 漏电、短路、倒送电、异常负荷、跳闸分析
- 现场安全边界
- 用电痕迹反推人的行为

主角不是道士，也不是职业驱鬼人。他逐渐学会识别某些无法完全用电工知识解释的“第二套规律”。

## 3. 核心叙事循环

每个章节遵循同一条大回路，但谜面与情绪必须变化：

1. **报修**：看起来是普通电气故障。
2. **现场**：按职业流程排除常见原因。
3. **矛盾**：出现至少一个违反常识的数据或物证。
4. **调查**：从电力资料、现场痕迹、住户口述、旧档案中收集证据。
5. **双重解释**：技术解释与民俗解释同时成立一部分。
6. **闭合选择**：玩家决定切断、恢复、旁路、保持断开，或以某种方式让“回路”完成。
7. **余波**：工单关闭，但某个细节留下总线剧情线索。

恐怖感来自“熟悉的工作流程里多出一个无法删除的变量”，而不是连续跳脸。

## 4. 游戏形态

- 横屏 16:9 为主。
- 2D / 2.5D 叙事 AVG。
- Visual Novel 是骨架，但场景调查与证据推理必须真实可玩。
- 轻解谜，不做复杂箱庭、不做完整 3D 自由移动。
- 每章约 30–60 分钟，后续可拆成 20–40 分钟单元。
- PWA 与 Windows 桌面端共享同一前端与剧情数据。

## 5. 美术方向

### 总体关键词

**潮湿、旧城、低照度、现实感、公共设施、纸面档案、低清数码、手绘人物、被雨水和时间侵蚀的城市。**

### 画面结构

- 背景：半写实现实环境，强调真实空间与中国城市细节。
- 人物：手绘 2D 立绘，避免过度萌系或纯日式校园 Galgame 观感。
- UI：像工作终端、旧工单、便携仪表与档案袋的混合体。
- 特殊媒介：旧照片、监控截图、聊天记录、工作票、配电图、抄表记录、手写门牌、丧葬用品。

### 色彩

主色不使用廉价的“纯黑 + 大红”。

- 常态：脏绿、青灰、水泥灰、钨丝灯黄。
- 异常：暗褐红、失真的暖白、低饱和纸黄。
- 红色仅作为危险、封印、错误信息或特殊叙事强调。

### 恐怖原则

- 不靠满屏血浆。
- 不用高频 Jump Scare 代替氛围。
- 人形异常应尽量“差一点正常”。
- 日常设施发生逻辑错误，比直接出现鬼脸更重要。
- 电、灯、表计、继电器、蜂鸣、雨声和远处广播是核心视听符号。

## 6. 世界观规则

“异常”不是统一的怪物体系，也不急于解释来源。玩家初期只知道：某些未完成的执念、仪式、死亡与记忆会借城市中的现实网络留下痕迹。

电网只是其中一个最容易被观测到的网络。

异常必须遵守自己的规则：

- 它可以制造不合理现象，但不能随意万能。
- 每章必须留下可回溯证据。
- 真相必须在揭晓后让玩家发现：之前的异常都能重新解释。
- 民俗线索不能只是百科知识问答，必须与人物关系和事件因果绑定。

## 7. 序章：《十三户》

当前 v0.1.0 已实现原型。

槐荫巷共有 12 户停电，但系统显示 13 块在线电表。主角到场后发现：

- 总开关拉开后仍有稳定反向电流；
- 新系统存在一个地址为空的“13号户”；
- 表箱封印螺丝后塞着干燥的黄纸灰；
- 巷子尽头唯一亮着的路灯不在现有配电图上；
- 旧宅暗线末端没有电器，只有一张七年前的讣告。

玩家第一次接触“不要急着切断异常回路”的原则。

## 8. 后续章节池

这些是方向池，不视为最终剧本：

### 第一章《头七》

同一条低压支线连续七天在凌晨固定时刻跳闸。第七夜之后，故障时间开始提前一分钟。

### 第二章《回送》

拆迁区没有住户，却持续向上级线路反送微小功率。现场所有电源都已拆除。

### 第三章《长明》

一盏没有电源的楼道灯多年不灭。真正断掉它之后，整栋楼开始有人失眠。

### 第四章《零线》

多个住户报告家中金属外壳带电，但现场测量全部正常。所有报修人都参加过同一场葬礼。

### 第五章《闭合》

前几章散落的户号、日期与线路编号在城市配电图上形成一个巨大闭环，总线剧情第一次明确显形。

## 9. 禁止事项

- 不把主角改成传统驱魔师。
- 不用“突然获得阴阳眼”快速解释一切。
- 不让每章都变成同一种鬼追人。
- 不为追求玩法硬塞战斗系统。
- 不做高成本完整 3D，除非后期证明核心体验需要。
- 不让手机端迫使桌面端改成竖屏；移动端优先横屏适配。
- 不在没有剧情功能的情况下堆中国符号。

## 10. 开发原则

先完成一个短而完整的恐怖循环，再增加章节长度。每次新增系统都问：它是否让玩家更像“在处理一个无法完全解释的故障”？如果答案是否定的，就不加入。

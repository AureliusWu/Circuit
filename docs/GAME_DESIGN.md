# 游戏设计规范

完整设定见 `PROJECT_BIBLE.md`。

## 核心体验

玩家每章都从一个可信的电气故障开始，通过职业流程把“正常原因”一层层排除，直到剩下一个无法被工程逻辑解释的变量。

## 必备系统

1. 叙事节点：人物对白、旁白、地点、时间。
2. 场景调查：热点或选项式检查，不依赖纯文本连续点击。
3. 证据记录：自动保存关键现场信息。
4. 推理节点：至少两种解释，错误判断产生可理解后果。
5. 存档：PWA 使用本地存储，桌面端当前共享同一前端逻辑。
6. 章节状态：后续拆为 JSON/TS 数据，避免剧情硬编码长期堆积在组件中。

## 单章节奏模板

- 0–10%：工单与生活化开场
- 10–35%：现场常规排障
- 35–60%：第一个不可解释矛盾
- 60–80%：调查、人物关系、民俗线索
- 80–95%：闭合选择 / 核心推理
- 95–100%：余波与总线伏笔

## 难度

解谜以“观察与因果”优先，不考专业电工知识。专业术语必须通过现场上下文让普通玩家也能理解。
